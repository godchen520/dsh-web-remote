# 机器人指令树状图

> 依据 `lib/index.mjs` 实际 dispatch 分支整理。
> 5 个通道（微信 / Telegram / QQ官方 / 钉钉 / 飞书）共用同一套指令，**完全一致**。

## 指令树

```
/帮助
 │
 ├─ /帮助 ······································ 显示本列表
 │
 ├─ /链接 ······································ 查看远程链接（未启动会自动开启）
 │    兼作「启动」：发它就会把远程服务拉起来，所以不再单列 /启动
 │
 ├─ /停止 ······································ 停止远程服务
 │
 ├─ /监听 ······································ 开关监听模式（会话思考完毕自动通知）
 │
 ├─ /状态 ······································ 查看通道状态
 │
 ├─ /会话列表 ·································· 列出所有可见会话
 │    过滤：排除「已归档 / 子代理 / 不属于任何 workspace 的孤儿」
 │    │
 │    └─ /选择N ································· 选中第 N 个会话
 │         │
 │         └─ 直接发送内容（无需前缀） ··········· 发到选中的会话
 │              未选择会话时提示：先 /会话列表 再 /选择 N
 │
 ├─ /当前会话 ·································· 查看选中的会话名称
 │
 ├─ /历史内容 ·································· 查看选中会话最近一次输出
 │
 ├─ /当前模型 ·································· 查看当前使用的模型（全局默认）
 │
 └─ /切换模型 ·································· 列出所有模型（⚙ = 支持思考强度）
      │
      └─ /切换模型N ····························· 选中第 N 个模型
           │
           └─ /选强度N ·························· 选择思考强度（0 = 默认）
                仅当所选模型支持思考强度时才走到这一层；
                不支持则第 2 步直接切换完成。
```

## 层级统计

| 层级 | 数量 | 指令 |
|---|---|---|
| **一级** | **10 条** | `/帮助` `/链接` `/停止` `/监听` `/状态` `/会话列表` `/当前会话` `/历史内容` `/当前模型` `/切换模型` |
| **二级** | 2 个 | `/选择 N`（挂在 `/会话列表`）、`/切换模型 N`（挂在 `/切换模型`） |
| **三级** | 1 个 | `/选强度 N`（挂在 `/切换模型 N`） |
| 用法（非指令） | 1 个 | 直接发送内容（挂在 `/选择 N` 之后） |

**帮助文本里只列一级的 10 条**，二三级用法收进所属一级的说明里（见 `HELP_LINES`）。

## 两条链的状态机

**会话链（两级）**

```
/会话列表  ──列出──▶  回复 /选择N  ──设置 st.selected──▶  直接发内容进该会话
```

**模型链（三级）**

```
/切换模型      第 1 步：列出模型，st.pick = { step:'model' }
     │
/切换模型N     第 2 步：选中第 N 个
     ├─ 模型支持思考强度 ──▶ st.pick = { step:'effort' } ──┐
     └─ 不支持 ──▶ 直接 switchModel() ✅ 完成              │
     │                                                     │
/选强度N   ◀───────────────────────────────────────────────┘
               第 3 步：0 = 默认，1..N = 具体强度
               ──▶ switchModel(provider, model, effort) ✅ 完成
```

## 关于 /启动

`/启动`（别名 `start` / `开启` / `start-remote`）在代码里**仍然可用**，但**不进帮助**——
`/链接` 已经承担了「未启动就自动启动」的职责，两者功能重叠：

| | 行为 |
|---|---|
| `/链接` | 未启动 → 自动启动 → 返回链接（一步到位，最常用） |
| `/启动` | 只启动 → 返回「远程服务已启动」，**不返回链接**，用户通常还要再发一次 `/链接` |

保留但不公开的理由：老用户可能已形成习惯，删掉会突然报「未知命令」；
不写进帮助则避免新用户困惑于「两个都能启动，该用哪个」。

> 微信通道**从未实现过** `/启动`（只靠 `/链接` 隐式启动）。
> 去掉 `/启动` 之后，5 个通道的指令集**完全一致**了。

## 帮助文本（只列一级）

`HELP_LINES` 的产出，微信与其它 4 通道共用（仅开头措辞不同）：

```
可用命令：
· /帮助 —— 显示本列表
· /链接 —— 查看远程链接（未启动会自动开启）
· /停止 —— 停止远程服务
· /监听 —— 开关监听模式（会话思考完毕自动通知）
· /状态 —— 查看通道状态
· /会话列表 —— 列出所有会话，回复「/选择 N」选中
· /当前会话 —— 查看选中的会话名称
· /历史内容 —— 查看选中会话最近一次输出
· /当前模型 —— 查看当前使用的模型
· /切换模型 —— 列出模型，回复「/切换模型 N」选中（可选思考强度）
· 直接发送内容（无需前缀）—— 发送到选中的会话
· 未选择会话时，先 /会话列表 再 /选择 N
```

## 改这块代码时的注意事项

1. **新增指令** → 加进 `HELP_LINES`（若是一级）；同时更新本文档与「通道支持矩阵」。
   测试守卫 #15 会检查 4 个非微信通道是否都接上了共享命令。
2. **新增二级/三级用法** → **不要**在 `HELP_LINES` 里单独占行，写进所属一级的说明。
   守卫 #27 会拦。
3. **不要列 `/启动`** → 守卫 #27 会拦；也不要顺手删掉 `/启动` 的实现（守卫会检查它仍在）。
4. 帮助文本只有 `HELP_LINES` 一处定义，两个入口（`WEIXIN_HELP` / `channelHelp()`）都必须引用它。
